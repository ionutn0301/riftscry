# RiftScry UI/UX audit — 2 November 2026

The review covers the home journey, Rift Atlas, champion roster and history, patch archive and comparison, automatic briefing, player lookup and profile, match review and AI entry, saved champions/findings, Notebook and missing-page recovery. Existing screenshots cover 100 route/viewport combinations; additional checks exercise state changes rather than just initial page loads.

## Findings and changes

| Priority | Finding | Resolution |
| --- | --- | --- |
| High | The returning-player privacy control was covered by the fixed dock in phone landscape. | Arrange the closed station in two columns, retaining 12px insets and 44px controls. Expanded disclosures return to normal document flow. Verify every control through rotation and hydration with full motion. |
| Medium | Narrow chapter tabs split labels into isolated letters. | Use short visible labels with complete accessible names. Wrap between words, with 11px text and 44px targets. |
| Medium | Invalid Riot IDs produced a message without marking or focusing the field. The two entry forms accepted different formats. | Apply the same validation limits, associate the error with the input, mark it invalid, focus it, and clear the field error when edited. Preserve input after network failure. |
| Medium | Search confused a failed or pending index request with a successful empty result. | Separate loading, failure, and no matches. Provide retry and a direct champion-browser fallback; retain the named search field with a clear accessible hint. Cancel abandoned or stalled requests. |
| Medium | Empty findings, past cards, and player Build Memory did not offer a clear primary next step. | Add direct actions into champion records, the game card, and recent matches. |
| Medium | Profile mode labels were cramped at 320px. | Use a three-column arrangement on narrow phones, with 44px controls and more readable labels. |
| Medium | Returning players still encountered exploration as the dominant homepage task. | Promote Continue briefing, preserve the cinematic entrance as a secondary action, and keep visual and keyboard order consistent. |
| Verification | A failed SSR player test prevented the production browser suite from starting. | Run production suites independently in desktop Chromium, mobile WebKit and mobile Chromium. Retain failures and visual evidence. |

## Verification contract

- Preserve the single shared dock and one-screen mobile homepage, including all three home findings and short landscape windows.
- Keep champion artwork pinned on desktop while the roster scrolls; prevent horizontal document overflow and unintended nested scroll areas.
- Check complete chapter names, touch targets, pointer hit testing, keyboard focus and Escape restoration.
- Exercise invalid input, failed requests, retry, useful empty-state actions, and returning-player state.
- Retain the existing checks for full-motion crossings, reduced motion, artwork failure, native history, theme persistence, and deliberate access to match AI analysis.
- Verify the archive's generated routes and underlying data contracts as well as browser presentation.

Browser screenshots and measurements are retained by the corresponding CI run. Player data is synthetic and browser-fixtured; this review does not prove uptime of Riot or model-provider services. No finite audit guarantees a flawless experience on every device; new observed regressions should become concrete checks.
